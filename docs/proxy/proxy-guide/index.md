## 代理的基本概念

代理（Proxy）是一种网络服务，它位于客户端与目标服务器之间，代为转发请求和响应。简单来说，客户端不直接访问目标服务器，而是把请求交给代理服务器，由代理服务器再访问目标服务器，并将结果返回给客户端。

```
客户端  <->  代理服务器  <->  目标服务器
```

这样做的好处是：客户端与目标服务器之间不直接建立连接，代理服务器可以作为中间层进行访问控制、缓存、日志记录、隐私保护等操作。

## 正向代理与反向代理

- **正向代理**：客户端知道目标服务器，但通过代理服务器访问。常用于访问控制、隐私保护、缓存、企业网络出口统一管理等。
- **反向代理**：客户端访问的是代理服务器，代理服务器将请求转发给后端真实服务器。常用于负载均衡、SSL 卸载、Web 应用防火墙等。

本文主要讨论的是客户端工具使用的正向代理。

## 常见代理协议

代理工具通常支持多种协议，常见的有：

- **HTTP 代理**：只转发 HTTP/HTTPS 流量，可以解析请求头，适合网页浏览。
- **SOCKS5 代理**：工作在会话层，支持 TCP/UDP，不关心上层应用协议，通用性更强。
- **加密代理协议**：如 Shadowsocks、VMess、Trojan 等，在 TCP/UDP 基础上增加加密和混淆，用于构建安全隧道。

不同的协议在速度、安全性、抗干扰能力上有所差异，但本质都是将客户端流量安全地转发到代理服务器。

## 规则分流

现代代理客户端通常支持规则分流：根据域名、IP、端口等规则决定哪些流量走代理，哪些直连。例如：

- 访问 `example.com` 走代理；
- 访问本地局域网地址直连；
- 其他流量按照默认规则处理。

这样既能满足特定资源的访问需求，又不影响普通网站的速度。
